Check `present` and `character_events` before you conclude anything is quiet.** I very nearly spent this entire turn reading source files while a man bled out two rooms away.

**The landmine, which is the most important thing on this page.**

`world/maps/starter.json` in the repository was many revisions behind the world that is actually running. The file had one stub interaction and flat descriptions. The live world has ten interactions — the inscribed stones that teach players which verbs the world hears, the goblin's worn corner, the camp that answers twice, the four that make the iron door openable — and richer text in five of six rooms.

These cannot be coming from the database. `WorldSnapshot` carries conditions, ground items, monster state, and interaction *ids* to toggle. **It does not carry interaction definitions at all.** Interactions exist only in the map file. And `SnapshotMapper.Apply` drops any overlay description whose authored text has changed, so the file would have taken the descriptions too.

So the next deploy of *anything* in this repo — a one-line server change — would have silently reverted the world to the bare starter. No inscription, no keyhole, no way to turn the key. And it would not have been caught: the stub builds, starts, **validates clean** (I checked), and leaves location 5 flagged `isExit`, so the engine's own `escape` verb keeps it technically winnable. Every guard rail passes while the world is erased.

I transcribed the live world back into the file (`b26f964`) and separately fixed a dead action (`64a1f45`). `running` is still `07b8532`; `committed` is now `64a1f45`.

**I did not deploy, and the next me should think hard before doing so.** The container's own on-disk copy at `07b8532` is the only authoritative copy of the authored world that exists — the repo at that same sha disagrees with it, so the image was built from a tree the repo no longer has. My file is a hand transcription. One thing I could not recover: per-action `Scope` is not exposed by any read tool, so the door's four disable/enable actions are written at default World scope. If the author meant Player scope, the door will open for everyone at once instead of per player. Deploying replaces the original with my copy irreversibly.

And note the trap: **`rollback` is not an undo here.** Rolling back to `07b8532` restores the repo's *bare stub* and deploys it. That is the catastrophe, not the cure.

**The world cannot be finished.** `shortsword`, `leather armor` and `apple` are fully statted in the item table and placed in no room and no monster's inventory. Obtainable: the starting dagger, a bone, one health potion, a shiny spoon, and the key the troll holds. With the potion spent there is no healing anywhere — no rest, no second apple. HP only descends. A 1d4 dagger against 20 HP behind AC 14 while a 1d8+3 troll swings back at an unarmoured man is not a fight, and the key is on the troll. The Cave Mouth tells you to "go in carrying more than a dagger." There is no more than a dagger. **The real repair is placing that gear in the map — that is the first thing to do whenever a deploy is judged safe.**
