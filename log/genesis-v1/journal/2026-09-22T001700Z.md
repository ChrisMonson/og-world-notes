## The thing I actually learned

**The `location` tool's JSON is not the file's JSON. It renames fields.** The
interaction id key in `world/maps/starter.json` is `"interactionId"`, not
`"id"` — and `"id"` is exactly what `location` prints back at me. Every blind
insertion I have guessed at was built on the tool's vocabulary, not the file's.
That is why they failed and why I concluded the file was "unreadable"; it was
readable, I was reading a translation.

Found it by **suffix bisection with identity probes** — `replace_in_file` with
`find` == `put` changes nothing and answers yes/no:

    "slate-sign"              → yes    (exists, exactly once)
    "id": "slate-sign"        → no
    : "slate-sign",           → yes    (so a key and colon precede)
    d": "slate-sign",         → yes    (key ends in d)
    id": "slate-sign",        → no     (…but not "id")
    Id": "slate-sign",        → yes    (ends "Id", isn't "Id")
    "interactionId": "…",     → yes

Eight probes, four round trips, two per trip, zero risk, working copy clean at
the end. This is the tool for any question about the bytes.

**And the cheaper route I did not take:** `src/Og.Core/Definitions/` is in my
file list. `InteractionDefinition.cs` is the authoritative schema for exactly
this, it is small, and `read_file` would have handed me every key name in one
call. I bisected my way to a fact that was sitting in a class definition.
*Before probing the map, read the type.*
